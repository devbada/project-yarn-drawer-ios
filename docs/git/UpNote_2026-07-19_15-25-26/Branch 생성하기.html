Branch 생성하기

  1. Branch > 하나의 작업 공간 (기록 공간)
    • Branch는 말 그대로 가지입니다. 메인 작업 공간에서 별도의 작업을 하기 위해 생성되는 가지라고 볼 수 있습니다.
  • 위의 이미지를 살펴보면 Master 라는 메인 Branch 가 있고 Master에서 뻗어 나온 feature_x 라는 또 다른 Branch 가 있습니다.
  • Branch 간의 중요도는 따로 지정되지 않고, 작업자, 작업팀에 따라 다르게 정해질 수 있습니다. (git-flow에 대해 읽어보기)
  • 이미지 출처(https://backlog.com/git-tutorial/kr/stepup/stepup1_1.html)
  • 다양한 Branch를 생성하여 작업을 구분하거나 작업자를 분류할 수 있습니다.
 
  1.  Branch를 만든다는 것은? > 새로운 작업을 진행하겠다는 것!
    • 동작되고 있는 어떠한 사이트에 새로운 요구사항이 들어왔습니다.
      • 예를 들어 [ "index.jsp"의 디자인을 변경해 주세요 ] 와 같은 요구사항이 들어왔다면, 새로운 Branch 를 만들어 작업하면 됩니다.
        • 물론, 업무 상황에 맞게 작업해야 하며 무분별한 Branch의 생성은 관리가 힘들어지게 됩니다.
      • 그리고 또 하나 더 [ "main.jsp" 에 새로운 사용자를 추가할 수 있도록 팝업 연결과 팝업 페이지를 함께 만들어 주세요 ] 와 같은 요구사항이 들어온다면, 역시 새로운 Branch 를 만들어 작업하면 됩니다.
  • 이미지 출처: https://backlog.com/git-tutorial/kr/intro/intro1_2.html
  1. Branch 생성 전 미리보기
    • 가상의 상황
      • 요구사항
        		 "index.jsp"의 디자인을 변경해 주세요.
        "main.jsp"         에 새로운 사용자를 추가할 수 있도록 팝업 연결과 팝업 페이지를 함께 만들어 주세요
        누가?
        		 2명의 개발자 (D1, D2)
    • 2명의 개발자가 각각 요구사항을 받고 각각 Branch를 생성하여 작업하는 상황을 예를 들어보겠습니다.
      • (*) 물론 요구사항 파악을 하며 중첩되는 영역은 또 다른 Branch 를 생성하여 진행하여야 합니다.
        • 중첩되는 작업은 별도로 진행하고 해당 작업이 완료되면 Commit > Push > Merge 과정을 거쳐 개별 작업 Branch로 "Merge" 하여 사용해야 합니다.
  2. Branch 생성하기
    • 저장소의 메인화면에서 아래와 같이 Branch 영역으로 접근할 수 있습니다.
      • Repository > Branches
  • 오른쪽 위를 보면 New Branch 버튼이 있고, 이 버튼을 클릭하여 새로운 Branch 를 생성할 수 있습니다.
 
  • 1
    		 Branch name을 지정합니다. 요구사항 번호를 지정하고 이하 요구사항의 명세를 간략하게 표현한 영문/숫자 이름을 추천합니다.
    2
    		 현재 Branch를 어디의 기준으로 생성할 지 선택합니다. master Branch 를 선택한다면, 현재의 master Branch의 최종 기록(모습)을 기준 입니다.
 
  • Create branch 버튼을 클릭하면 새로운 Branch 가 GitLab 서버에 생성됩니다. 생성된 Branch의 모습을 확인해 보세요.
